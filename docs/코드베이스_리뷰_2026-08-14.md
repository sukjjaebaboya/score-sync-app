## 4. 우선순위별 핵심 결함

## P0 - 출시 차단

### P0-01. PDF 캔버스가 흰 화면으로 남음

- 파일: `src/components/PdfPage.tsx:14-29`
- 관련 파일: `src/components/ScoreViewer.tsx:36-50`, `src/components/ScoreViewer.tsx:182-207`

#### 증상

- `bassoon.pdf`가 35페이지로 정상 인식된다.
- 첫 페이지 canvas 크기도 생성된다.
- 그러나 악보가 그려지지 않고 흰 화면만 표시된다.
- 확대 버튼을 눌러도 다시 렌더링되지 않는다.

#### 코드 원인

`renderedRef.current`를 렌더 완료 전에 `true`로 바꾸고 있다. 렌더가 실패하거나 PDF 이미지 의존성이 준비되지 않아도 React 상태 변경이 없으므로 렌더를 다시 시도하지 않는다.

또한 `active === false`가 되면 canvas 대신 placeholder를 반환해 canvas DOM이 사라진다. 그러나 `renderedRef.current`는 그대로 `true`다. 페이지가 다시 활성화되면 새 canvas가 생성되지만 코드는 이미 렌더했다고 판단해 그리지 않는다.

확대율 `scale`이 변경돼도 `renderedRef.current === true`이면 다시 렌더하지 않으므로 기존 bitmap을 새 크기로 다시 생성할 수 없다.

#### 영향

- 앱의 핵심 기능인 악보 읽기가 불가능하다.
- 가상 스크롤로 한 번 화면 밖에 나간 페이지가 다시 흰 화면이 될 수 있다.
- 확대 시 해상도와 좌표가 맞지 않을 수 있다.

#### 권장 수정

- 렌더 여부를 단순 boolean이 아닌 `page + scale + canvas instance` 기준으로 관리한다.
- `RenderTask`를 ref에 보관하고 effect cleanup에서 `cancel()`한다.
- canvas가 새로 마운트되거나 scale이 바뀌면 반드시 다시 렌더한다.
- 렌더 성공 후에만 완료 상태를 기록한다.
- 렌더 실패 시 오류 상태와 재시도 버튼을 제공한다.
- PDF.js 이미지 준비 경고가 발생하는 테스트 PDF를 회귀 테스트에 포함한다.

#### 완료 조건

- 최초 업로드 후 3초 이내에 첫 페이지 악보가 보인다.
- 페이지 1 → 페이지 5 → 페이지 1로 이동해도 악보가 유지된다.
- 100% → 150% → 80% 변경 후 글자와 오선이 다시 선명하게 렌더링된다.
- 35페이지 전체에서 빈 canvas가 발생하지 않는다.

## P1 - 데이터 무결성 및 핵심 사용성

### P1-01. YouTube 프로젝트가 로컬 영상으로 저장됨

- 파일: `src/types.ts:19-24`
- 파일: `src/components/Toolbar.tsx:35-45`
- 파일: `src/App.tsx:32-42`

`ProjectFile.media.provider` 타입이 `"local"` 하나만 허용하고, 저장 코드도 항상 `provider: "local"`을 기록한다.

실제 테스트 JSON:

```json
{
  "media": {
    "provider": "local",
    "fileName": "youtube:Sm4JaV6Xz0M"
  }
}
```

#### 영향

- JSON만 보고 어떤 영상으로 만든 기록인지 안정적으로 판단할 수 없다.
- 향후 YouTube 자동 복원과 다른 파트 타임라인 재사용이 어렵다.

#### 권장 모델

```ts
type MediaSource =
  | { provider: "youtube"; videoId: string }
  | { provider: "local"; fileName: string; sha256?: string };
```

### P1-02. 다른 PDF·영상의 JSON을 검증 없이 적용함

- 파일: `src/lib/db.ts:61-76`
- 파일: `src/components/Toolbar.tsx:48-57`

현재 JSON 검증은 `schemaVersion === 2`와 `anchors`가 배열인지 여부만 확인한다. 현재 열려 있는 PDF의 SHA-256, 페이지 수, 영상 ID와 비교하지 않는다.

#### 영향

- 다른 파트나 다른 판본의 좌표가 현재 PDF에 표시된다.
- 페이지 범위를 벗어난 앵커는 `anchorDocumentY()`에서 0으로 처리되어 첫 페이지로 잘못 이동한다.
- 사용자가 틀린 악보를 보며 연습할 수 있다.

#### 권장 수정

- Zod 또는 JSON Schema로 모든 필드를 검증한다.
- `pageIndex`, `xRatio`, `yRatio`, `timeSec` 범위를 검증한다.
- 현재 `videoId`와 `pdf.sha256`이 다르면 자동 적용하지 않는다.
- 불일치 시 `취소`, `사본으로 불러오기`, `타임라인만 가져오기`를 구분한다.

### P1-03. IndexedDB가 모든 프로젝트에 단일 키를 사용함

- 파일: `src/lib/db.ts:3-5`
- 파일: `src/App.tsx:20-45`

모든 자동 저장이 `project/current` 하나를 덮어쓴다. 앱 시작 시 파일을 선택하기 전에 이 레코드의 앵커를 복원한다.

#### 영향

- 이전 PDF의 앵커가 새 PDF에 남을 수 있다.
- 다른 영상으로 바꾸어도 기존 타임코드가 이어질 수 있다.
- 사용자가 어떤 프로젝트가 복원되었는지 알 수 없다.

#### 권장 수정

- 프로젝트 키를 `media fingerprint + PDF SHA-256`으로 만든다.
- YouTube는 `youtube:<videoId>:<pdfHash>`를 사용한다.
- 로컬 영상은 가능하면 영상 SHA-256 또는 명시적인 프로젝트 ID를 사용한다.
- PDF 선택 전에는 앵커를 실제 편집 상태에 적용하지 않는다.
- 최근 프로젝트 목록과 삭제 기능을 제공한다.

### P1-04. 영상과 PDF를 선택한 뒤 교체할 수 없음

- 파일: `src/components/VideoPanel.tsx:154-174`
- 파일: `src/components/Toolbar.tsx:73-81`

#### 권장 수정

- 툴바에 `PDF 변경` 버튼을 둔다.
- 변경 전에 저장되지 않은 앵커가 있으면 JSON 백업을 안내한다.
- 새 파일 선택 시 기존 앵커를 유지할지, 지울지, 사본으로 만들지 선택하게 한다.

### P1-05. YouTube URL과 API 오류 처리가 충분하지 않음

- URL에서 추출한 ID를 모든 경로에서 11자 규칙으로 다시 검증하지 않는다.

- Player `onError` 코드별 사용자 메시지를 제공한다.
- 재생 상태를 `unstarted | playing | paused | buffering | ended | error`로 구분한다.

`loadPdfDocument()`와 페이지 로딩 체인에 catch가 없다. 암호화, 손상, 너무 큰 PDF에서 사용자에게 오류를 보여주지 못한다.

또한 모든 페이지 proxy를 순차적으로 얻은 뒤 한 번에 상태에 넣기 때문에 큰 문서에서 첫 화면 표시가 늦어진다.

#### 권장 수정

- 첫 페이지를 우선 로드하고 나머지 메타데이터를 점진적으로 준비한다.
- 로딩 진행률과 취소 버튼을 제공한다.
- 암호화 PDF, 손상 PDF, 페이지 수 상한 오류를 구분한다.
- PDF worker 오류를 Error Boundary 밖으로 전파하지 않는다.

### P2-03. 서로 다른 페이지 크기와 회전 처리가 불완전함

- 파일: `src/components/ScoreViewer.tsx:61-79`

첫 페이지의 원본 폭으로 전체 PDF의 scale을 계산한다. 다른 크기나 회전 방향의 페이지가 섞이면 폭 맞춤이 틀릴 수 있다.

#### 권장 수정

- 페이지별 원본 폭으로 개별 scale을 계산한다.
- 좌표 공간을 회전 적용 후 viewport 기준으로 명시한다.
- 화면 회전·확대 후 현재 앵커가 같은 focus 위치에 오도록 재배치한다.

### P2-04. JSON 검증과 다운로드 호환성이 약함

- 파일: `src/lib/db.ts:49-76`

#### 문제

- JSON 필드 타입과 범위를 검증하지 않는다.
- 미래 버전 마이그레이션 경로가 없다.
- object URL을 클릭 직후 즉시 revoke한다. 일부 Safari 환경에서는 다운로드가 시작되기 전에 URL이 해제될 위험이 있다.

#### 권장 수정

- 스키마 검증과 명시적 마이그레이션 함수를 둔다.
- 다운로드 anchor를 DOM에 붙이고 클릭 후 제거한다.
- object URL은 다음 task 또는 짧은 timeout 후 revoke한다.
- JSON 파일명에 PDF명, 영상 ID, 수정 날짜를 포함한다.

### P2-05. 로컬 영상 object URL이 해제되지 않음

- 파일: `src/components/VideoPanel.tsx:114-120`

`URL.createObjectURL(file)`로 생성한 URL을 소스 변경이나 컴포넌트 해제 시 `URL.revokeObjectURL()`하지 않는다. 긴 영상이나 반복 교체 시 메모리를 불필요하게 잡을 수 있다.

### P2-06. 태블릿 악보 우선 레이아웃이 충분하지 않음

- 파일: `src/components/VideoPanel.css:1-8`
- 파일: `src/components/Toolbar.css:11-16`
- 파일: `src/components/Toolbar.css:76-90`

실제 768×1024 세로 테스트에서 영상이 화면 높이의 약 42%를 차지했다. 하단 툴바가 두 줄 이상으로 늘어나면서 악보 영역이 줄었다.

앵커 행의 버튼은 높이 26px로 태블릿 터치 목표인 44~48px보다 작다.

#### 권장 수정

- 세로 화면에서 영상 높이를 25~30vh로 낮춘다.
- `연습 모드`에서는 앵커 목록과 보조 설정을 접는다.
- 앵커 보정 버튼은 최소 44px로 키운다.
- 핵심 버튼과 편집 버튼을 분리한 하단 시트를 사용한다.
- 광고 슬롯을 추가하더라도 악보 높이를 침범하지 않게 한다.

### P2-07. 자동 스크롤 effect가 빈번히 재생성됨

- 파일: `src/components/ScoreViewer.tsx:96-140`

YouTube 현재 시간이 약 100ms마다 Zustand 상태로 갱신되고 `currentTime`이 RAF effect 의존성에 포함되어 있다. 따라서 requestAnimationFrame 루프가 빈번히 취소·재생성된다.

#### 권장 수정

- RAF 루프는 컴포넌트 수명 동안 유지한다.
- 최신 시간과 설정은 ref 또는 store의 `getState()`로 읽는다.
- React 렌더링이 필요한 표시 시간은 더 낮은 빈도로 분리한다.

### P2-08. 자동 저장 오류가 사용자에게 보이지 않음

- 파일: `src/App.tsx:20-45`
- 파일: `src/lib/db.ts:7-43`

IndexedDB 열기 또는 트랜잭션 실패가 처리되지 않는다. 시크릿 모드, 저장 공간 부족, 브라우저 데이터 정책으로 실패해도 사용자는 저장된 것으로 오해할 수 있다.

#### 권장 수정

- 저장 상태를 `저장 중 / 저장됨 / 저장 실패`로 표시한다.
- 실패 시 JSON 백업 버튼을 강조한다.
- 앱 시작 시 저장소 사용 가능 여부를 한 번 확인한다.

## 5. 보안 및 개인정보 리뷰

### 긍정적인 점

- PDF는 브라우저에서 `ArrayBuffer`로 처리된다.
- 자체 백엔드나 업로드 API가 없다.
- YouTube ID를 iframe API에 전달하며 임의 HTML을 렌더링하지 않는다.
- 모자이크는 프레임 다운로드 없이 CSS 레이어로 처리된다.

### 개선할 점

- JSON은 외부 입력이므로 완전한 런타임 검증이 필요하다.
- YouTube 호스트와 ID 검증을 강화해야 한다.
- 정적 호스팅 응답에 CSP, Referrer-Policy, Permissions-Policy를 설정해야 한다.
- 오류 분석 도구를 추가한다면 PDF명, 해시, 영상 URL, 앵커 데이터가 로그에 포함되지 않게 해야 한다.
- 광고 도입 시 YouTube/광고 사업자 통신과 쿠키 사용을 개인정보처리방침에 분리해 설명해야 한다.
- 서버 DB가 없다는 것은 외부 통신이 없다는 뜻이 아니다.

## 6. 코드의 좋은 점

### 6.1 계산 로직 분리

`src/lib/geometry.ts`가 앵커 정렬, 좌표 환산, 선형 보간, dead zone 계산을 UI와 분리한다. 단위 테스트를 추가하기 좋은 구조다.

### 6.2 단순한 상태 모델

`FOLLOWING`, `PEEKING`, `RETURNING` 세 상태는 현재 제품 범위에 적합하다. 실제 테스트에서도 수동 스크롤, 일시정지 유지, 재생 복귀가 예상대로 전환됐다.

### 6.3 로컬 우선 처리

PDF 해시, IndexedDB, JSON 다운로드를 사용해 서버 없는 구조의 방향을 잘 따르고 있다.

### 6.4 모자이크 격리

영상 콘텐츠, 모자이크 레이어, 앱 조작부가 CSS 레이어로 구분되어 있다. 실제 테스트에서 영상 내용이 충분히 흐려지고 앱 버튼은 정상적으로 사용할 수 있었다.

### 6.5 빌드와 정적 검사 통과

TypeScript 빌드와 Oxlint가 현재 코드에서 오류 없이 통과한다. 타입과 린트 기반은 유지할 가치가 있다.
